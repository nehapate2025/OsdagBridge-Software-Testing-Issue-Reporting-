## 6. CODE-LEVEL ROOT CAUSE ANALYSIS

For each confirmed bug:

1. Reproduce the issue using the recorded input configuration.
2. Inspect the actual affected source code.
3. Identify the relevant function or method.
4. Trace the affected data flow.
5. Identify the root cause where evidence supports it.
6. Suggest a concrete code-level correction.

Where the exact root cause cannot be established, state:

"Root cause not yet confirmed."

Do not invent source locations, function names, or code snippets.

Do not modify engineering calculations simply to remove a failing test.

## 7. GITHUB EXISTING ISSUE SEARCH

Repository:

https://github.com/Nidhikhare12/OsdagBridge

Before creating any issue:

- Search the repository's existing open issues.
- Search closed issues.
- Search issue titles and descriptions.
- Search for similar symptoms and affected modules.
- Compare the exact trigger conditions.
- Check whether an existing issue already covers the same bug.

Do not create duplicate issues.

If an existing issue covers the same problem:

- Record its issue number.
- Record its URL.
- Document any additional findings.
- Prepare an additional comment where appropriate.

If no matching issue exists, prepare a new issue.

## 8. GITHUB ISSUE STRUCTURE

For each confirmed, previously unreported bug, prepare a detailed issue using the following structure:

### Title

A short, specific description of the defect.

### Description

Explain the affected module and the problem.

### Environment

Record:

- Operating system.
- Python version.
- Conda environment.
- Application version or commit where available.
- Relevant dependencies.

Do not invent environment details.

### Steps to Reproduce

Provide exact numbered reproduction steps.

### Input Configuration

Provide the complete relevant input parameters and units.

### Expected Behavior

Explain what should happen.

### Actual Behavior

Explain what actually happens.

### Logs and Evidence

Attach or reference:

- Tracebacks.
- Screenshots.
- Input Dictionary.
- Output Dictionary.
- Relevant execution logs.

### Suspected Source Code Location

Identify:

- Python source file.
- Function or method.
- Relevant dictionary key, if applicable.

### Suggested Fix

Provide a concrete technical correction or code snippet where justified.

Clearly distinguish confirmed root causes from suspected causes.
