# OsdagBridge Automated Testing Framework and Results Repository

## Overview

This directory (`test_results/`) stores all automated testing records, execution logs, test case registers, and persistent engineering evidence generated by the OsdagBridge test framework.

The testing infrastructure was established to provide rigorous, production-grade quality assurance for the OsdagBridge plate girder bridge analysis and design suite without altering core engineering algorithms.

---

## Directory Structure

```
test_results/
├── README.md                  # This documentation file
├── test_case_register.csv     # Master register of all defined test cases, IDs, and statuses
├── test_execution_log.csv     # Execution history appended automatically on every test run
└── evidence/                  # Persisted runtime artifacts, JSON snapshots, and verification charts
    ├── *.json                 # Serialized input and output dictionary snapshots
    ├── *.txt                  # Diagnostic logs and error traces
    └── *.png                 # Headless Matplotlib verification charts (300 DPI)
```

## Master Test Case Register (`test_case_register.csv`)

The test case register maintains canonical traceability for all test cases implemented across the codebase.

### Column Schema

| Column | Description |
| :--- | :--- |
| `Test Case ID` | Standardized identifier (e.g., `OSB-UNIT-xxx`, `OSB-INT-xxx`, `OSB-GEO-xxx`, `OSB-MAT-xxx`, `OSB-RUN-xxx`, `OSB-REP-xxx`) |
| `Module` | Relative path to the test module containing the test |
| `Test Function` | Exact Python test function name |
| `Category` | Categorization (`Unit / IO`, `Unit / Validation`, `Unit / Material`, `Unit / Dictionary`, `Integration / API`, `Integration / CLI`, `Integration / BOQ`, `Scenario / Geometry`, `Scenario / Material`, `Scenario / State Isolation`, `Reporting / Evidence`) |
| `Input Configuration` | Concise summary of input parameters used |
| `Expected Result` | Defined engineering or structural assertion |
| `Execution Status` | Current execution status (`PASS`, `FAIL`, or `BLOCKED`) |
| `Dependency / Blocker` | Missing external requirement (e.g. `OpenSeesPy`) or `None` |

## Test Execution Log (`test_execution_log.csv`)

Every execution of `pytest` hooks into `pytest_runtest_makereport` in `tests/conftest.py` to record each individual test outcome.

### Column Schema

1. **`Execution ID`**: Unique identifier for the run (`EXEC-xxxxxx`).
2. **`Date and Time`**: Timestamp formatted as `YYYY-MM-DD HH:MM:SS`.
3. **`Test Case ID`**: Extracted from test docstring `Test Case ID: OSB-...` or function name.
4. **`Application Version`**: SemVer version of OsdagBridge (`1.0.0`).
5. **`Input Summary`**: Summary of input data exercised.
6. **`Result`**: Exact result (`PASS`, `FAIL`, or `BLOCKED`).
7. **`Duration`**: Test execution duration in seconds (`0.xxx s`).
8. **`Error Log`**: Truncated trace or reason if skipped/failed.
9. **`Evidence Path`**: Path to associated snapshot in `test_results/evidence/`.

## Evidence Directory (`test_results/evidence/`)

The evidence directory stores persistent verifiable artifacts produced during test runs:
- **Input Snapshots**: Complete JSON dumps of input parameter dictionaries (`valid_baseline_input`, `modified_geometry_input`, etc.) ensuring no silent field corruption.
- **Output Snapshots**: Complete JSON dumps of design calculation results, governing combinations, and DCR utilization sets.
- **Engineering Charts**: High-resolution PNGs produced headless via `chart_utils.py`, validating graph rendering independently of the UI.
- **Diagnostic Error Logs**: Trace logs captured when out-of-bounds parameters are handled.

## Running the Test Suite

Run all tests using the project's Python environment:

```bash
# Run the complete test suite with verbose output
python -m pytest -v --tb=short

# Run only unit tests
python -m pytest -v -m unit

# Run only integration tests
python -m pytest -v -m integration

# Run scenario tests (geometry, materials, consecutive runs)
python -m pytest -v -m scenario

# Run reporting and evidence generation tests
python -m pytest -v -m reporting
```

### Dependency Handling & Blocked Status Policy

In environments where optional compiled finite element solvers (such as `OpenSeesPy`) are not installed, tests requiring those components gracefully skip and register as `BLOCKED` with explicit diagnostic messages. They are never reported as `PASS` (which would be false evidence) nor allowed to cause an unhandled crash.
